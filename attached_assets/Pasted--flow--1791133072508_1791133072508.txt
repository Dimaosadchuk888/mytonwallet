

ТЗ: проверить клики кнопок и добавить понятную реакцию интерфейса
Есть проблема с кнопками в flow подключения и проверки кошелька.
1. Кнопки периодически перестают реагировать
Например:
• нажимаю «Подключить кошелёк»;
• происходит переход в MetaMask;
• возвращаюсь обратно;
• если подключение/операция завершилась ошибкой или была отменена, нажимаю кнопку повторно;
• кнопка может вообще не реагировать на тап.
То же самое может происходить с:
• «Подключить кошелёк»;
• «Проверить кошелёк»;
• Approve / Activate automatic withdrawal;
• кнопкой повторной попытки после ошибки.
Иногда повторный клик начинает работать только через несколько секунд или после полного закрытия и повторного открытия приложения.
Похоже, что после предыдущего запроса остаётся какой-то loading, pending, lock, mutex, overlay или другое состояние, которое блокирует повторный вызов.
Что проверить
Найди причину, почему после неудачного/отменённого flow кнопка остаётся фактически некликабельной.
Особенно проверить:
• loading states;
• pending states;
• isConnecting;
• isSigning;
• isApproving;
• disabled;
• mutex/debounce/lock;
• незавершённые promises;
• WalletConnect/Reown session state;
• обработчики reject, error, disconnect, timeout;
• не остаётся ли невидимый overlay поверх интерфейса;
• не блокируется ли повторный вызов после возврата из MetaMask;
• корректно ли состояние сбрасывается после ошибки или отмены.
Очень важно: если пользователь вернулся из MetaMask после ошибки или отмены, он должен иметь возможность сразу нажать кнопку повторно, без ожидания и без перезапуска приложения.
Если кнопка визуально доступна, но тап по ней ничего не делает — это нужно исправить.


⸻


2. Клик должен быть визуально понятен
Сейчас пользователь может несколько раз тапать по кнопке и не понимать, был ли зарегистрирован тап.
Нужно добавить нормальное визуальное состояние нажатия:
Обычное состояние
Активировать автоматические выплаты
↓
При тапе
кнопка визуально реагирует на нажатие — например, лёгкое изменение масштаба/яркости/состояния.
↓
Запрос запущен
Выполняется...
с индикатором загрузки.
↓
MetaMask открылся / ожидаем подтверждение
кнопка должна быть заблокирована только пока действительно выполняется текущий запрос, а не на неопределённое время.
↓
Ошибка / отмена
кнопка снова становится активной:
Попробовать снова
И пользователь может нажать её сразу же.


⸻


3. Особенно важно для Approve
Сейчас кнопка Approve / Activate automatic withdrawal находится внутри большой карточки третьего этапа.
Я бы хотел, чтобы она визуально привлекала внимание, но без агрессивной анимации.
Например:
• лёгкая анимация появления;
• мягкий pulse/glow;
• небольшое изменение состояния при наведении/тапе;
• после нажатия сразу переход в Выполняется....
Главное — пользователь должен понимать:
«Вот эту кнопку сейчас нужно нажать, чтобы перейти к запросу в кошельке».
При этом не нужно автоматически запускать approve без действия пользователя.


⸻


Главное требование
Проверь всю цепочку:
Кнопка → tap → обработчик → запуск WalletConnect/Reown → MetaMask → возврат → success/error → сброс состояния → возможность повторного нажатия.
Мне важно, чтобы каждый реальный тап по активной кнопке либо запускал действие, либо сразу показывал пользователю понятное состояние, а не создавал ситуацию, когда пользователь нажимает несколько раз и ничего визуально не происходит.
Сначала найди причину блокировки повторных кликов, затем исправь её минимально, не ломая существующий wallet flow.
