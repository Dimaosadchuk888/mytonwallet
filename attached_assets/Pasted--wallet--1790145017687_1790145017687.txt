### 2. Ethereum Wallet

Существующую Ethereum-интеграцию **не ломать и не переписывать без необходимости**.

После подключения показывать:

* название кошелька;
* сокращённый адрес;
* сеть;
* актив;
* статус;
* кнопку `Проверить кошелёк`.

Пример:

> Ethereum Wallet
> `0xfD39...65ed0e`
> Ethereum Mainnet · USDT
> 🟡 Требуется проверка
>
> **Проверить кошелёк**

---

### 3. Проверка Ethereum

Сделать отдельный пошаговый flow:

**Шаг 1 из 3 — Проверка кошелька**

Показывать:

* подключённый адрес;
* Ethereum Mainnet;
* USDT;
* понятное описание того, что происходит.

Не использовать расплывчатые формулировки вроде `Confirm required wallet permissions`, если речь идёт о конкретном blockchain permission.

Перед любой подписью/разрешением **обязательно показывать пользователю фактические параметры операции**, например:

* тип разрешения;
* токен;
* сеть;
* адрес контракта;
* spender;
* лимит/условия разрешения.

Никакие параметры разрешений не скрывать от пользователя.

### 5. Архитектура под будущий TON Connect

Сделать интерфейс так, чтобы после подключения TON Connect можно было просто заменить адаптер:

```text
WalletProvider
 ├── EthereumWalletProvider
 └── TonWalletProvider
```

TON provider пока должен иметь статус:

```text
not_configured
```

а после настоящей интеграции:

```text
disconnected
connecting
connected
verifying
verified
error
```

Не привязывать UI напрямую к TON Connect. Сделать отдельный adapter/service слой.

### 6. Единая система статусов

Использовать одинаковую систему для Ethereum и TON:

* ⚪ Не подключён

* 🟡 Требуется проверка
* 🔵 Проверка
* 🟢 Подтверждён
* 🔴 Ошибка

После успешной проверки:

> 🟢 **Подтверждён**
> Адрес добавлен в белый список.

### 9. Самое важное перед завершением

Проведи аудит текущей реализации White List и перед изменениями определи:

1. где находится UI White List;
2. где реализовано подключение Ethereum;
3. где реализован Permit2/approve flow;
4. где формируются wallet requests;
5. где обрабатываются `cancel/rejected/error`;
6. где находится текущая локализация;
7. есть ли уже заготовка под TON/Gram;
8. какие зависимости нужны для будущего TON Connect.

**Не переписывать рабочую blockchain-логику только ради нового дизайна.**

После изменений проверить:

* RU;
* EN;
* Ethereum connect;
* Ethereum disconnect;
* cancel wallet request;
* rejected signature;
* wallet provider unavailable;
* повторное подключение;
* refresh страницы;
* отсутствие подключённого TON Connect;
* отсутствие ошибок JavaScript в console.
