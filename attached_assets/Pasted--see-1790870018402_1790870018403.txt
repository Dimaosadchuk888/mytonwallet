Да. Это можно сделать аккуратно, и логика здесь должна быть именно такой: проверку/подтверждение seed-фразы убрать из обязательной цепочки регистрации, но оставить её доступной позже в кабинете.

Дай агенту такую задачу:

Упростить onboarding кошелька Gram Wallet

Сейчас после создания кошелька пользователь вводит пароль, после чего его перекидывает на экран «Кошелёк готов!» / повторный ввод и проверка seed-фразы. Из-за этого регистрация получается длиннее.

Нужно изменить UX:

Для создания нового кошелька:

1. Пользователь нажимает «Создать кошелёк».
2. Проходит стандартный процесс создания кошелька.
3. Задаёт пароль и подтверждает его.
4. После успешного создания кошелька сразу автоматически перенаправить пользователя в личный кабинет / главный экран Gram Wallet.
5. Не требовать на этом этапе копировать seed-фразу, вставлять её обратно и проходить обязательную проверку.
6. В личном кабинете оставить заметное напоминание о необходимости сделать резервную копию/сохранить seed-фразу.
7. Пользователь уже по своему желанию должен иметь возможность открыть раздел резервной копии и пройти проверку seed-фразы позже.

Важно:

• Не удалять механизм резервного копирования и проверки seed-фразы — только сделать его необязательным на этапе первичной регистрации.
• Не изменять существующую генерацию, шифрование или хранение ключей.
• Seed-фраза не должна отправляться на сервер, в API, аналитику или логи.
• Не делать автоматическую передачу seed-фразы из одного экрана в другой.
• После создания кошелька пользователь должен попасть непосредственно в кабинет уже авторизованным.

Для импорта существующего кошелька: не ломать текущий flow импорта — если для восстановления кошелька требуется seed-фраза/приватный ключ, этот обязательный этап должен остаться.

Итоговый UX

Создать кошелёк → пароль → готово → личный кабинет

А уже в кабинете:

«Сделайте резервную копию кошелька» → открыть позже → показать seed-фразу → при необходимости пройти проверку.

Проверь также, чтобы после изменения не было циклического редиректа обратно на экран проверки seed-фразы и чтобы состояние созданного кошелька корректно сохранялось после перезапуска приложения.
